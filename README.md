# Tattoo Instagram AI agent

AI-агент отвечает клиентам тату-мастера в Instagram Direct. Решения и правила описаны в [CLAUDE.md](CLAUDE.md).

## Запуск локально

```bash
pip install -r requirements-dev.txt
python -m pytest
uvicorn app.main:create_app --factory --port 8000
```

Развёртывание на Railway, подключение Telegram и Meta, анализ старой переписки: [docs/DEPLOY.md](docs/DEPLOY.md).

## Эндпоинты

| Путь | Назначение |
|---|---|
| `GET/POST /webhooks/instagram` | проверка и приём webhook Meta (подпись `X-Hub-Signature-256`) |
| `POST /webhooks/telegram` | кнопки и ответы менеджера (заголовок `X-Telegram-Bot-Api-Secret-Token`) |
| `GET /privacy` | публичная политика конфиденциальности для App Review |
| `GET /data-deletion` | инструкция по удалению данных (требование Meta) |
| `GET /playground?token=…` | тестовый чат с ботом без Instagram |
| `GET /auth/instagram/start?token=…` | ссылка, по которой мастер подключает свой Instagram |
| `GET /admin/analysis?token=…` | анализ переписки (через API или загруженную ZIP-выгрузку) и черновики базы знаний |
| `GET /health` | проверка живости |

Webhook Telegram и подписку аккаунта Instagram сервер ставит сам при старте.
Команды в Telegram-группе: `/chatid`, `/personal @ник`, `/bot @ник`, `/forget @ник`, `/learn`, `/rules`, `/unrule N`.

Обучение: бот запоминает, как менеджер исправляет черновики и отвечает сам (только в тату-диалогах). Раз в неделю (понедельник, после сводки) или по `/learn` модель предлагает правила, каждое приходит в Telegram с кнопками «Принять» / «Отклонить». Принятые правила сразу попадают в системный промпт.

## Как это работает

1. Webhook проверяет подпись, отбрасывает дубли по `mid` и сохраняет сообщение.
2. Через `DEBOUNCE_SECONDS` все новые сообщения клиента уходят модели одним ходом.
3. Если клиент написал «human» или «менеджер», код сам передаёт диалог менеджеру, без вызова модели.
4. Модель отвечает или вызывает инструмент. Эскалация и заявка присылают карточку в Telegram и ставят статус «менеджер».
5. Код добавляет раскрытие «я AI-ассистент» в начале диалога, после паузы больше 24 ч и после «Вернуть боту».
6. В режиме одобрения ответ приходит черновиком с кнопками «Отправить», «Исправить», «Забрать диалог».
7. Перед отправкой проверяется 24-часовое окно. Бот никогда не пишет первым, даже после «Вернуть боту».

Сообщение из Instagram или Business Suite, которое отправило не наше приложение, ставит диалог на паузу.
Своё эхо бот узнаёт по `mid`, а если эхо пришло раньше ответа API, то по тексту.

## Какие диалоги ведёт бот

Webhook Meta присылает серверу все сообщения аккаунта, отфильтровать их на стороне Instagram нельзя. Поэтому фильтр стоит первым шагом, до любых ответов:

1. **Пришёл из рекламы** («Написать в Direct», в webhook есть `referral` с `source: ADS`): диалог сразу про тату.
2. **Личный контакт** из списка (`/personal @ник` в Telegram-группе): бот молчит всегда.
3. **Мастер написала первой**: это её переписка, бот молчит.
4. **Переписка была до запуска бота** (`BOT_LAUNCH_DATE`): бот молчит, мастер ведёт диалог как раньше. Проверяются только даты сообщений через API, текст старой переписки не читается.
5. **Новый контакт:** первые сообщения оценивает Haiku 5.5: `tattoo`, `not_tattoo` или `unclear`. При «неясно» («Привет!», одно фото) бот ждёт следующих сообщений, после трёх неясных оставляет диалог мастеру.

Из диалогов не про тату ничего не хранится: ни текст, ни ник, ни фото. В Telegram они не попадают, только число в ежедневной сводке. Ответ мастера в таком диалоге тоже не пересылается.
`/bot @ник` отдаёт боту диалог, который фильтр оставил мастеру. Бот ответит на следующее сообщение клиента, первым он не пишет.

Классификатор видит первые сообщения новых контактов, это единственное, что из таких диалогов уходит в Anthropic. Выключить фильтр: `TOPIC_FILTER=false`.

## Claude API

- Модель задаётся `CLAUDE_MODEL`, глубина рассуждений `CLAUDE_EFFORT`. На Opus 5.5 thinking нельзя отключить, поэтому экономия идёт через effort.
- Системный промпт и инструменты не меняются между запросами, история диалога только дописывается. Так работает кэш промпта и не ломаются блоки thinking (preserved thinking). Всё, что происходит между ходами (ответ менеджера, правка черновика, неотправленный ответ), модель получает заметкой в начале следующего хода клиента.
- Единственная правка истории: удаление сообщения по уведомлению Meta. Для этого в запросе стоит `prefix_mismatch_behavior: "drop_block"`, API отбрасывает устаревшие блоки thinking, а не возвращает ошибку.
- Для Opus 5.5 и Sonnet 5.5 включён серверный `fallbacks: "default"`: при отказе модели запрос повторяется на другой модели. Если отказ всё же пришёл, клиент получает шаблон, а диалог уходит менеджеру.
- Принудительный `tool_choice` на Opus 5.5 не поддерживается, модель выбирает инструменты сама (`auto`, `strict: true`).
- Кэш начинает работать, когда префикс длиннее минимума модели. С пустой базой знаний промпт короткий и может не кэшироваться, после заполнения базы проверьте `cache_read_input_tokens`.
- Фото-референсы модель видит (`ATTACH_IMAGES=true`). Картинка скачивается сразу при получении, пока ссылка Instagram CDN жива, и загружается в Files API Anthropic. В историю идёт блок `image` с `file_id`, он не меняется между ходами и читается из кэша. Файл живёт 90 дней, удаляется вместе с сообщением по уведомлению Meta и при очистке. Если скачать не удалось, модель видит пометку `[attachment: image]` и просит прислать референс ещё раз. Ссылки на фото по-прежнему приходят в карточку заявки.
